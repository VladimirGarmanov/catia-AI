# CATIA V5 + Codex на Windows — один агент

## Резервный путь через весь рабочий стол — без подтверждений

По явному запросу пользователя UI доступен без отдельных подтверждений.
При ошибке MCP агент смотрит экран и частичные результаты перед восстановлением.
При COM_TIMEOUT переход заблокирован до выяснения результата исходного вызова.
После UI-операции нужны повторное чтение модели и проверка размеров.

Драйвер встроен в тот же MCP: `catia_ui_snapshot` возвращает PNG всех мониторов
и приложений, `catia_ui_action` отправляет ввод без окна Yes/No. Привязки
к процессу CNEXT, документу, заголовку и snapshot_id больше нет. COM-подключение
для UI не требуется. Скриншот может включать личные данные из других приложений.
Без второго сервиса, API-ключа или отдельного computer-use плагина.

После получения этой версии: закрой Codex, запусти `INSTALL.cmd`, затем
`START_CATIA_AI.cmd` или `START_SMART_DRAWING.cmd`. `/mcp` должен показывать
135 инструментов полного сервера; inspection остаётся 13. INSTALL устанавливает
Windows-зависимости pywin32 и Pillow автоматически.

Для первого теста попроси только `catia_ui_snapshot`. Затем проверь клик и ввод
в пустом несохранённом документе. Снимок и его размер,
координаты при Windows DPI и фактическую доставку ввода нужно
проверить на живой Windows — offline-тесты этого не доказывают.

Поддержаны левый/правый/средний и двойной клик, клавиши, сочетания клавиш,
Unicode-текст и прокрутка. Drag пока не реализован. Координаты относительно
левого верхнего угла снимка всех мониторов. Каждый ввод требует уникальный
request_id для защиты от повторов. После действий сверяй экран и модель.
Не запускай второй сервер/автоматизацию параллельно.
Не трогай мышь и клавиатуру в момент отправки ввода.

Требуется разблокированный интерактивный Windows-сеанс. Ввод идёт в текущее
окно, даже если это не CATIA. Доступ ко всему UI не разрешает агенту выполнять
несвязанные с задачей удаления, публикации или покупки.
Не запускай CATIA от администратора ради обхода
ограничений: [Windows SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)
ограничен уровнем привилегий. При блокировке — IT, не обход политик.

Один Codex читает чертёж и выделение, составляет план, сам вызывает инструменты
CATIA и проверяет результат. Субагенты и cad_executor больше не требуются.
Отдельного платного AI API в Python-сервере нет.

## После обновления API-пакета

В этой версии регистрируются **135 инструментов**, исходные 81 имени сохранены.
Работа с существующим эскизом и новый справочник описаны в `CAA_MIGRATION.md`.
После копирования обновлённого исходного проекта закрой старую сессию Codex,
выполни `INSTALL.cmd`, затем `DIAGNOSE.cmd` и `START_CATIA_AI.cmd`.
Повторная установка нужна также для регистрации включённого API-каталога.
На Mac MCP подключать к CATIA не нужно. Изменения пока локальные, сами по себе
они не появляются в скачанном ранее ZIP или установленном EXE.

Агент сначала читает `catia_get_model_state`, затем `catia_list_objects`.
Новые операции по handles требуют `document_id`, `expected_revision` и
уникальный `request_id`. После ошибки — инспекция, без повторного создания.
Для оси вращения есть `catia_sketch_line(as_axis=true)` и
`catia_sketch_set_axis`; ось исключается из контура через Construction.
`catia_capability_status` ищет API в приложенном справочнике, но не исполняет
неподдержанные команды. Полная матрица и Windows-проверки:
[IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

## Чертёж: Astra → Luna medium автоматически

В исходной папке запусти `START_SMART_DRAWING.cmd`, выбери PDF/изображение
и напиши задачу. Astra анализирует страницы; при нехватке размеров вопросы
появляются в терминале. Ответь там же (`/cancel` отменяет). Когда план готов,
launcher сам открывает интерактивный Codex на `gpt-6-luna`, reasoning `medium`.
Дальше общаешься с Luna обычным образом; она сначала подтверждает целевой
документ и начало моделирования. Команда `/model` позволяет вручную вернуться
к сильной модели при сложной переработке.

Это два последовательных процесса, не субагенты и не незаметная подмена модели
внутри TUI. Передаются исходные страницы, подробный BRIEF.md и все уточнения
в `.local/handoffs/<id>/conversation.json`. Внутренние рассуждения не переносятся.
Каждый раунд анализа получает все предыдущие уточнения. CATIA MCP отключён
на этапе планирования; исполнитель использует обычное полное подключение.
Планировщик работает в read-only sandbox; другие пользовательские MCP не
меняются, поэтому запускать следует только с доверенными интеграциями.

Нужен вход в Codex и доступ аккаунта к обеим моделям. При ошибке анализа или
невалидном ответе переключения нет; автоматического fallback на другую модель
нет. Используется установленный Codex, без отдельного платного API в сервере.
Первый запуск может потребовать предварительного входа через обычный START.
Режим пока не проверен end-to-end на Windows; тесты этого изменения не запускались.
Основа: [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
(`exec`, изображения, structured output), затем обычный интерактивный запуск.

## Полная EXE-сборка

Полная сборка `CATIA-AI-Setup.exe` устанавливает всё в профиль Windows текущего
пользователя: Codex CLI, автономный Python 3.13.3, CATIA MCP и зависимости,
включая PDF/изображения. Отдельно искать Node, ставить Python, Git или запускать
PowerShell не нужно. Установщик не требует прав администратора.

Чтобы скачать сборку из GitHub: открой **Actions → Build CATIA AI Windows
installer → Run workflow**, дождись завершения, открой завершённый запуск и
скачай artifact `CATIA-AI-Windows-Installer`. Распакуй artifact, запусти
`CATIA-AI-Setup.exe`, оставь выбранный ярлык и запусти **CATIA AI** после
установки. При первом запуске войди в Codex через ChatGPT. Для сборки нужен
Windows x64; она пока создаётся вручную из GitHub Actions и не является
постоянной кнопкой Download на странице репозитория.

Установщик содержит автономный Codex `codex.exe`; поэтому Node в этой сборке
не нужен. Python и пакет MCP лежат рядом с приложением в его пользовательской
папке и не меняют системный PATH. Архив Codex проверяется по SHA-256 из
официального GitHub release. Обновление — установить новую сборку поверх старой;
пользовательские настройки Codex не перезаписываются.

## Установка из исходного ZIP

Для исходного ZIP нужны Windows x64, CATIA V5 и разрешённый доступ к
python.org, nodejs.org, PyPI/npm. Git и заранее установленный Node не нужны.
`INSTALL.cmd` сам подготавливает недостающие зависимости.
Git, администраторские права и изменение ExecutionPolicy не нужны.

1. Скачай и полностью распакуй ZIP. Открой папку с INSTALL.cmd.
2. После первой установки обновляй проект двойным нажатием UPDATE.cmd. Он сам
   скачает последнюю версию с GitHub и обновит файлы в этой папке; ZIP вручную
   скачивать, распаковывать и удалять не нужно. Для этого нужен доступ к GitHub.
   Обновление сохраняет .venv/runtime, .local, .codex/config.toml, traffic и
   локальные CAD/чертежи. Устаревшие файлы не удаляются автоматически.
   Не запускай две копии проекта одновременно.
3. Дважды нажми INSTALL.cmd. Дождись Setup complete и Exit code: 0.
4. Открой CATIA. Старый чат Codex заверши.
5. Дважды нажми START_CATIA_AI.cmd — либо START_WITH_DRAWING.cmd для выбора чертежа.
   При необходимости войди в Codex и доверь только папку этого проекта.

INSTALL переиспользует Node/Codex, в том числе сохранённые пути в
.local/windows-runtime.json, %LOCALAPPDATA%/codex-cli и Node ZIP в Downloads.
Если Node не найден, INSTALL скачивает официальный Node 24 LTS ZIP, сверяет
SHA-256 с nodejs.org и распаковывает в `.local/node` — выбирать файл вручную не нужно.
Codex устанавливается через официальный `@openai/codex` в `.local/codex`.
Способ npm-установки соответствует [официальной документации OpenAI](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).
Если Python не найден, на Windows x64 скачивается официальный установщик 3.13.3;
перед запуском проверяются Authenticode и издатель Python Software Foundation.
Python ставится в `.local/python`, окружение проекта — в `.venv`.
Системный PATH не меняется. Для проверки подписи используется одна read-only
команда PowerShell, без изменения ExecutionPolicy. Если PowerShell, загрузки или
запуск EXE запрещены политикой, установка останавливается: обратись к IT.
Не перемещай проект после установки Python/venv; сразу распакуй ZIP в постоянную папку.
Этот bootstrap проверен offline; выполнение на чистой Windows ещё нужно проверить.
Если Codex отсутствует, npm устанавливает его локально в .local/codex.
Без Node допустим уже установленный самостоятельный codex.exe.

Установка добавляет зависимости для PDF/изображений, проверяет пакет и MCP.
setup_codex.ps1 оставлен только как обёртка над INSTALL.cmd; если PowerShell его
блокирует, используй .cmd. Никакого Bypass.

## Что изменилось в подключении

START передаёт Codex настройки через параметры только текущего запуска:

- agents.enabled=false — без создания субагентов;
- catia-v5 — полный сервер через абсолютный путь к Python проекта (venv в
  исходном ZIP или встроенный Python в полной установке);
- catia-v5-inspect — отключён в этой сессии, с полным определением транспорта.
- Для catia-v5 задано `default_tools_approval_mode='approve'`: обычные вызовы
  его MCP-инструментов разрешены заранее, без подтверждения каждого шага.
  Это включает инструменты изменения модели и работы с документами; агент
  всё равно должен соблюдать задачу и требовать явную команду и путь для
  сохранения/перезаписи. Разрешения терминала и других серверов не меняются.
  Настройка применяется после нового запуска через START, не в старом чате.
  Отдельные политики инструментов и ограничения организации могут требовать
  подтверждение независимо от настройки по умолчанию.

Параметр описан в [документации MCP](https://learn.chatgpt.com/docs/extend/mcp).

Основной .codex/config.toml, личные настройки Codex и старые файлы ролей не
перезаписываются. Прежняя глобальная регистрация inspect остаётся на диске, но
в запущенной через START сессии отключена. Другие MCP-настройки не меняются.
Используется документированный механизм
[CLI overrides](https://learn.chatgpt.com/docs/config-file/config-advanced).
Не запускай просто codex и не возобновляй старый инспекционный чат: они могут
использовать прежние настройки. Системный PATH тоже не меняется.

В новом чате /mcp должен показывать включённый catia-v5 с 135 инструментами.
Стартовый запрос проверяет инструменты САМОГО главного агента: catia_new_part,
catia_pad, catia_get_model_state, catia_get_selection, catia_screenshot.
Эта проверка ничего не строит. После PASS можно дать конкретную задачу.

## Чертёж: фото или PDF

START_WITH_DRAWING.cmd открывает окно выбора PNG, JPEG или PDF. Все страницы PDF
рендерятся локально в PNG и прикладываются к начальному сообщению Codex по порядку.
Исходный файл не меняется. Копии находятся в .local/drawings; это локальные файлы,
но при запуске они передаются Codex как вложения — выбирай только разрешённые для
передачи чертежи.

Лимиты: 50 MB, PDF от 1 до 12 страниц; 144 dpi с ограничением 4096 пикселей на
сторону. Если страниц больше, весь документ отклоняется, а не обрезается молча.
Для мелких размеров приложи крупный фрагмент. HEIC сначала экспортируй в PNG/JPEG.
PDF с паролем нужно заранее открыть и экспортировать разрешённую незашифрованную
копию. Фото детали без размеров не позволяет восстановить точную геометрию.

Картинку также можно вставить в интерактивный Codex; см.
[официальную инструкцию по изображениям](https://learn.chatgpt.com/docs/image-inputs).
Выбор файла сам по себе НЕ разрешает построение. После разбора чертежа напиши:

> Создай НОВУЮ деталь — кронштейн по приложенному чертежу; размеры, которых не
> видно, сначала уточни. Работай сам, без субагентов. Другие документы не меняй.
> После построения обнови модель, проверь размеры и покажи скриншот. Не сохраняй.

Если размеры и разрешение уже даны, агент должен выполнять задачу, а не только
останавливаться на плане. Но полностью автоматическое построение произвольной
детали по любому фото не гарантируется.

## Первый безопасный тест без чертежа

После PASS в START_CATIA_AI.cmd:

> Создай одну НОВУЮ несохранённую CATPart. В ней построй прямоугольник 40 x 20 мм
> на плоскости XY и Pad толщиной 5 мм. Сам выполни построение через MCP, без
> субагентов и Python COM-скриптов. Другие документы не меняй. Обнови модель,
> проверь размеры 40 x 20 x 5 мм по доступным данным и покажи скриншот.
> Не сохраняй и не закрывай документы. При ошибке остановись и сообщи её.

Правила AGENTS.md: состояние и выделение → одно действие → update → состояние
и измеримые размеры → скриншот → проверка. Самопроверка не равна независимой
экспертизе. Во время построения не переключай активный документ и не запускай
другую CAD-автоматизацию.

## Выделение и ограничения

Можно спросить: «Что открыто?», «Что я выделил?», «Какой размер у этой фичи?».
Чтение выделения и модели сохранено; обновление выбранной поддерживаемой
фичи/эскиза работает с текущим COM-объектом, не с сохранённым ID.

Fillet/Chamfer и Shell/Thickness теперь пробуют использовать непосредственно
выбранное ребро/грань через COM Reference. Этот путь пока **не проверен на
Windows CATIA**: сначала испытывай его на новой несохранённой детали и после
операции проверяй геометрию и размер. Hole использует позиционирующий эскиз.
Списка стабильных ID рёбер по-прежнему нет; имена и индексы не подходят для
точного выбора. Draft и точный bounding box явно возвращают unsupported.
Скриншот возвращает изображение MCP и путь; разрешение определяется окном
CATIA, параметры width/height не принимаются.

## Диагностика

### Проверка исправления размеров эскиза

В старой реализации `catia_sketch_constraint` код радиуса был ошибочно равен 1
(Distance) вместо 14 (Radius), а геометрия передавалась без `Reference`.
Исправлены коды всех поддерживаемых ограничений и создание COM-ссылок.
Проверка чтением `Dimension.Value` подтверждает установленное значение, но
не доказывает, что эскиз решён или полностью определён.

После переноса обновлённого кода на Windows заверши старый Codex и запусти
`START_CATIA_AI.cmd` заново, чтобы перезапустить MCP. Для проверки дай запрос:

> Создай одну новую несохранённую CATPart и эскиз XY. Создай окружность радиусом
> 10 мм. Прочитай catia_sketch_get_geometry, найди именно созданную окружность
> по текущему списку и добавь ей ограничение radius = 25 мм. Индекс заранее не
> угадывай. Закрой эскиз и обнови деталь. Проверь параметр радиуса 25 мм и
> отсутствие ошибки обновления. Если параметр недоступен, сообщи, что его
> нужно проверить вручную в CATIA. Другие документы не меняй, ничего не сохраняй.

В CATIA вручную проверь размер R25, статус ограничения и отсутствие конфликта.
В отдельных тестовых эскизах проверь длину одной линии (`distance` с одним
индексом), расстояние между двумя объектами, угол, horizontal/vertical,
parallel/perpendicular, coincidence, tangent и fix. Не накладывай все эти
ограничения сразу на одну пару объектов: они могут противоречить друг другу.
Эти Windows-проверки пока не выполнены; offline-тесты используют COM-моки.

Если ошибка сообщает, что ограничение создано, но размер не установлен или
не подтверждён, остановись: оно осталось в эскизе. Не повторяй добавление
автоматически, чтобы не создать дубликат. Сохрани полный текст ошибки и аргументы.

### Проверка запуска MCP

DIAGNOSE.cmd проверяет эффективные настройки ЭТОГО запуска и реальный stdio
discovery: 135 полных / 13 инспекционных инструментов. Инспекционный процесс
проверяется отдельно, но в интерактивной одноагентной сессии он отключён.
Ни один инструмент CATIA при диагностике не вызывается.

Логи: .local/diagnostics.log, .local/setup.log, .local/start.log.
Просмотри локальные пути перед отправкой. MCP JSON с секретами и чат не логируются.
Если диагностика PASS, но в чате нет инструментов, пришли ошибку запуска MCP
и результат /mcp — не повторяй установку бесконечно.

Windows .cmd, отображение вложений, доступ инструментов внутри нового чата,
COM-построение и размеры требуют живой проверки. Offline-тесты этого не доказывают.
Если университет блокирует запуск программ или загрузку пакетов, обратись к IT.

## Приёмка ремонтного задания (30.09.2026)

После обновления проекта перезапусти Codex/MCP. На **новой несохранённой** детали
проверяй операции по одной, начиная с простой геометрии: arc и sketch
constraint; shell/thickness и fillet/chamfer по свежему выделению; hole, shaft,
groove, mirror и patterns; затем GSD и сборку в отдельной новой CATProduct.
После каждой операции прочитай состояние и фактический параметр/геометрию.
Если COM-операция создала частичный объект и затем ошиблась, остановись и
осмотри дерево — автоматический повтор может сделать дубликат.

`catia_draft`, `catia_get_bounding_box` и стабильная адресация из
`catia_list_edges` пока не реализованы: сервер отказывает явно. Матрица
инерции/центр масс и физические единицы `catia_measure_distance` также требуют
калибровки на Windows; частичный ответ не является полной приёмкой. Исправленные
аргументы COM и ответы других инструментов здесь на Mac не проверялись на CATIA.

Для Shaft эскиз должен содержать профиль и ось, либо после закрытия эскиза
выбери прямую ось и вызови `catia_shaft` с `axis_from_selection=true`.
Для GSD `catia_gsd_revolve` передай имя профиля и `axis_from_selection=true`
при выделенной прямой оси; ось должна лежать в плоскости профиля. Имена осей
допускаются только как уникальный fallback. Оба варианта нужно проверить на
новой несохранённой детали: COM `Reference` и выбор границы зависят от CATIA.
