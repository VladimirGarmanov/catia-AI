# CATIA AI на Windows

В папке проекта всего четыре кнопки:

| Файл | Для чего |
| --- | --- |
| `INSTALL.cmd` | Первая установка или восстановление зависимостей |
| `START_AI.cmd` | Обычный запуск: выбор клиента и режима |
| `UPDATE.cmd` | Обновление файлов проекта с GitHub без Git |
| `DIAGNOSE.cmd` | Проверка выбранного клиента и MCP без операций в CATIA |

## Первый запуск из ZIP

1. Распакуй ZIP в постоянную локальную папку. В ней должны лежать эти четыре
   файла, `scripts` и `catia_mcp`. Не запускай из окна просмотра ZIP.
2. Открой `INSTALL.cmd`. Выбери **1 — Codex**, **2 — Claude Code** или **3 — оба**.
   Он использует существующий Python либо скачивает официальный Python x64;
   создаёт `.venv`, устанавливает пакет и нужные зависимости. Если выбранному
   клиенту нужен Node и его нет, Node скачивается автоматически в `.local/node`.
   Отдельно искать Node ZIP, устанавливать Git или выполнять PowerShell-скрипты
   не требуется. Интернет нужен; если сеть/политика блокирует загрузку, установка
   останавливается с сообщением, не отключая ограничения Windows.
3. Открой CATIA V5. Запусти `START_AI.cmd`, выбери клиент и режим.
4. Войди в аккаунт клиента, если потребуется. У Codex и Claude отдельные аккаунты;
   доступ к одному не даёт доступ к другому. Отдельного AI API внутри сервера нет.

Повторная установка использует найденные программы. Внутри проекта сохраняются
`.venv` и `.local`; системный PATH и `.codex/config.toml` не переписываются.
Администратор и изменение ExecutionPolicy не нужны. Бинарники клиентов не
обновляются автоматически при каждом запуске.

## Режимы в START_AI

После выбора клиента:

1. **Chat** — работа с открытой моделью, без выбора входного файла.
2. **One drawing** — выбрать один PDF, PNG или JPEG.
3. **Multiple files + parallel planning team** — выбрать несколько файлов
   через Ctrl/Shift; главный агент раздаёт анализ независимым агентам, затем
   объединяет планы и сам выполняет CATIA-команды. См. [TEAM_WORKFLOW.md](TEAM_WORKFLOW.md).
4. **Astra analysis, then Luna conversation** — только Codex: анализ одного
   чертежа и уточнения через Astra, затем интерактивный чат с Luna medium.
   Нужен доступ к обеим моделям. При ошибке анализа переключение не происходит.

**0** отменяет меню; отмена выбора файла не запускает AI-клиент.
Chat/One drawing работают одним агентом. Team — параллельный анализ и
последовательные команды в одну CATIA. Smart и Team не совмещаются.
Не запускай два CAD-writing клиента одновременно: общей межпроцессной COM-блокировки нет.

Можно обойти меню одной командой из PowerShell в папке проекта:

```powershell
.\START_AI.cmd --client codex --mode chat
```

```powershell
.\START_AI.cmd --client claude --mode team
```

```powershell
.\START_AI.cmd --client codex --mode drawing --drawing "C:\Drawings\bracket.pdf"
```

```powershell
.\INSTALL.cmd --client claude
```

## Чертёж и первый тест

PDF превращается в упорядоченные PNG-страницы. HEIC сначала экспортируй в
PNG/JPEG. Оригиналы не изменяются; страницы и командные отчёты остаются в `.local`.
В Chat изображение также можно приложить средствами самого клиента.

Первый запрос без чертежа:

> Создай одну новую несохранённую деталь Test. Создай эскиз прямоугольника
> 40 × 20 мм на плоскости XY и Pad высотой 10 мм. Прочитай фактические размеры.
> Другие документы не изменяй, ничего не сохраняй.

С чертежом:

> Создай кронштейн по приложенному чертежу в новой детали; размеры, которых
> не видно, сначала уточни. Ничего не сохраняй без моего указания пути.

Fix и AutoConstraint запрещены. Проверка ограничений описана в
[SKETCH_CONSTRAINT_STATUS.md](SKETCH_CONSTRAINT_STATUS.md): удовлетворённость
отдельных constraints не доказывает fully constrained. Непроверенные DOF
возвращаются как unknown. Уточняй отсутствующие размеры, не угадывай масштаб фото.

## Если нет инструментов или запуск не удался

Запусти `DIAGNOSE.cmd` и выбери тот же клиент. Без меню:

```powershell
.\DIAGNOSE.cmd --client codex
```

Проверяются пути, версия клиента и реальный MCP stdio discovery.
Сейчас сервер регистрирует **166 full / 13 inspection** инструментов.
В рабочем чате включён полный `catia-v5`; inspection-транспорт отключён.
Введи `/mcp` в выбранном клиенте и попроси найти `catia_new_part`, `catia_pad`,
`catia_get_model_state`, `catia_get_selection`, `catia_screenshot` без их вызова.

Логи находятся в `.local/setup.log`, `.local/start.log`, `.local/diagnostics.log`.
Они показывают, из какой папки и каким Python идёт запуск. Проверь личные пути
перед отправкой. PASS диагностики означает доступность транспорта, не успешное
построение и не гарантию, что модель увидела инструменты внутри чата.

Codex получает MCP-параметры только на текущий запуск через
[CLI overrides](https://learn.chatgpt.com/docs/config-file/config-basic).
Claude использует `.local/claude-mcp.json` и обычные разрешения своего клиента.
Пользовательские и организационные настройки не заменяются. Если нужного
клиента нет, выполни INSTALL и выбери его; запуск сам ничего не устанавливает.

Ошибка `This Claude Code version lacks --append-system-prompt-file` в старом
launcher была ошибкой нашей проверки: скрытый флаг может отсутствовать в
`claude --help`. Новый launcher вообще не использует этот флаг. Claude стартует
из папки проекта и читает `CLAUDE.md`, который подключает `AGENTS.md` через
[поддерживаемый импорт](https://code.claude.com/docs/en/memory#import-additional-files).
Оба файла должны быть в папке проекта; их полный текст не передаётся в командной
строке Windows. После получения исправленных файлов достаточно запустить
`START_AI.cmd` → Claude Code → Chat. Переустанавливать Node или менять
ExecutionPolicy из-за этой ошибки не требуется.

## Обновление и старые файлы

Закрой оба AI-клиента, дождись завершения операций CATIA, затем запусти
`UPDATE.cmd`. Он скачивает опубликованную `main` из `VladimirGarmanov/catia-AI`.
Локальные неопубликованные изменения с GitHub получить нельзя: UPDATE может
заменить их опубликованной версией. Не запускай его поверх своей разработки.

Обновление сохраняет `.venv`, `.local`, runtime, модели, чертежи и настройки.
Известные устаревшие кнопки и две старые Windows-инструкции удаляются;
неизвестные пользовательские файлы не удаляются. При переходе со старого
обновлятора оставшиеся старые кнопки уберёт первый новый START_AI или INSTALL.
Архивные папки не создаются. Обычный DIAGNOSE не выполняет эту очистку.

Старые ярлыки вне папки проекта могут ссылаться на удалённые кнопки: направь
свой ярлык на `START_AI.cmd`. Нужна одна рабочая папка, повторно скачивать и
распаковывать проект для каждого сеанса не надо.

## Полный установщик EXE

`CATIA-AI-Setup.exe` содержит Python, зависимости MCP и Codex. После установки
используй один ярлык **CATIA AI**: это то же меню START_AI. Для добавления Claude
открой INSTALL в папке установленного проекта и выбери Claude; нужен интернет.
Изменения исходников не обновляют уже скачанный EXE: нужна новая Windows-сборка.
При изменении bundled-зависимостей UPDATE попросит новый EXE.

Offline-тесты на Mac не проверяют Windows `.cmd`, вход в аккаунты, доступ моделей,
диалог выбора файлов в bundled Python или живое построение через CATIA COM.
Эти проверки остаются для Windows. Если file picker недоступен, launcher
предложит вставить путь к файлу прямо в окно (Explorer → Copy as path).
Для нескольких файлов — по одному пути на строку, затем пустая строка;
`0` отменяет весь выбор. Альтернатива — `--drawing`, как в примере выше.
