# CATIA V5 + Codex на Windows

Скачай проект ZIP-архивом и **извлеки всё**. Открой вложенную папку, где лежит
`INSTALL.cmd`. Git не нужен. Не переноси с Mac `.venv` или `.local`.
Нужны Windows, Python 3.10+ (на целевом ПК есть 3.13.3), разрешённый доступ
к PyPI/npm и установленная CATIA V5. Запуск программ должен быть разрешён IT.

1. Дважды нажми **`INSTALL.cmd`**. Дождись `Setup complete` и кода выхода 0.
2. Запусти CATIA обычным способом.
3. Дважды нажми **`START_CATIA_AI.cmd`**. Войди в ChatGPT, если Codex попросит,
   и подтверди доверие только папке проекта.

Установщик переиспользует имеющиеся Node/Codex, включая прошлую установку в
`%LOCALAPPDATA%\codex-cli` и Node ZIP с двойной вложенностью в Downloads.
Если Node не найден, появится окно выбора **`node.exe`**. Сначала скачай
[Node.js LTS для Windows](https://nodejs.org/en/download) как Standalone Binary ZIP,
извлеки весь архив и выбери файл. Сам Node установщик не скачивает.
Без Node можно использовать уже установленный самостоятельный `codex.exe`.
Если Codex отсутствует, он устанавливается через npm в `.local/codex` проекта.

Пути сохраняются в `.local/windows-runtime.json`; системный PATH не меняется.
Поэтому используй START, а не набирай `codex` в произвольном новом терминале.
Не перемещай папки Node/проекта после установки. Если переместил — повтори INSTALL;
конфликтующая MCP-запись от другой папки потребует явного разбора, не перезаписи.

INSTALL создаёт `.venv`, устанавливает пакет с `pywin32`, проверяет регистрацию
81/13 инструментов и реальное MCP stdio discovery **без вызовов инструментов CATIA**.
Он добавляет `catia-v5-inspect` главному чату и абсолютные пути в шесть файлов ролей.
Основной `.codex/config.toml` не меняется. Первые версии изменённых файлов ролей
сохраняются в `.local/role-backups`. Чужие/отключённые MCP-записи не заменяются.
Глобальный включённый `catia-v5` считается конфликтом, а не удаляется автоматически.

START проверяет конфигурацию и запускает новую сессию Codex. Если версия поддерживает
`--no-daemon`, используется отдельный процесс, чтобы не переиспользовать старую сессию.
Это предосторожность, **не доказанное исправление наследования MCP**.
Стартовый запрос сам просит вызвать роль `cad_executor` только для проверки наличия
`catia_new_part` и `catia_pad`, не для построения. До PASS не начинай моделирование.
В главном чате `/mcp` должен показывать 13 инструментов `catia-v5-inspect`, а не полный
доступ. Подробный порядок ролей — [MULTI_AGENT.md](MULTI_AGENT.md).

## Если что-то не работает

Дважды нажми **`DIAGNOSE.cmd`** и пришли `.local/diagnostics.log` вместо ручного набора
команд. При неудачной установке нужен `.local/setup.log`, при запуске — `.local/start.log`.
В логах есть локальные пути: просмотри перед отправкой. Содержимое Codex auth-файлов,
переменные MCP с секретами и интерактивный чат в эти логи не копируются.

Диагностика разделяет: корректность TOML/путей, запуск настоящих stdio-серверов и
**непроверенный** доступ инструментов внутри агента Codex. Последний подтверждается
только в живой сессии: нужны фактический вызов spawn и сообщения запуска MCP.
Уже наблюдалась ситуация, когда инспекция работала, а исполнитель получал только
инспекционные инструменты. Установка файлов сама по себе не доказывает исправление.

Новые `.cmd` не запускают PowerShell и не используют Bypass, активацию `.venv`,
права администратора или изменение политик. Если университет блокирует сам запуск
`.cmd`, Python, Node или загрузку пакетов — остановись и обратись к IT.
Старый `setup_codex.ps1` оставлен для совместимости; при его блокировке не проси
агента повторять запуск или менять ExecutionPolicy.

Первый безопасный тест — **только новая деталь**:

> Используй CAD-команду из AGENTS.md. Сначала inspector и planner, затем проверка
> плана и один executor. Подключись через `catia_connect`, прочитай состояние,
> создай новую CATPart через `catia_new_part`,
> снова прочитай состояние и выделение. Спроси у меня размеры прямоугольника и
> толщину; после подтверждения создай Sketch и Pad. Обнови деталь, проверь дерево
> и параметры, сделай `catia_screenshot`. Затем независимый verifier проверяет
> модель и изображение. Не меняй другие
> открытые документы и не сохраняй ничего без моей команды и явного пути.

Для каждой модификации держи цикл: **прочитать состояние и выделение → выполнить
одно действие → обновить деталь → прочитать состояние и размеры → сделать
скриншот → проверить результат**. Скриншот возвращается как MCP image content и
путь к сохранённому файлу, если клиент Codex отображает изображения от MCP.
Используй `.jpg`; фактическое разрешение задаётся окном CATIA, параметры
`width`/`height` инструмент не принимает. Числа и дерево проверяй отдельно:
картинка не доказывает точность размера или успешность операции.

Проверка выделения/топологии на живой CATIA:

```powershell
.venv\Scripts\python.exe scripts\selection_probe.py
```

Запусти её по очереди без выделения, с выбранным Pad/Sketch, затем с гранью и
ребром **новой тестовой детали**. Скрипт только читает текущее выделение. Он
покажет, доступны ли `SelectedElement.Type`, `Value`, `Document`, `Reference` и
`Reference.DisplayName` именно в университетской CATIA. После изменения геометрии
повтори проверку: старое имя/индекс нельзя автоматически использовать как точную
ссылку. Точное адресование выбранной грани/ребра в Fillet, Chamfer, Hole или
Sketch пока **не реализовано и не подтверждено**; `catia_list_edges` явно
сообщает об ограничении и не очищает выделение. Следующий этап — на отдельной
тестовой детали проверить передачу live `SelectedElement.Reference` в конкретные
COM-фабрики и отклонение устаревших ссылок после update.

Если прикладываешь чертёж в чат Codex, используй запрос:

> Создай кронштейн по приложенному чертежу; размеры, которых не видно, сначала уточни.

Изображение прикладывается **в Codex**, не в Python-сервер. Невидимые размеры
автоматически восстановить нельзя. Тесты на Mac проверяют только Python/MCP
контракт с COM-моками; живые вызовы CATIA, её лицензия, диалоги и скриншот
проверяются только на Windows.
