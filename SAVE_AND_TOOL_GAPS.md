# Сохранение и журнал недостающих инструментов

## catia_save_document

Перед сохранением прочитай модель и закрой серверный Sketch. Нужен явный
абсолютный путь, document_id, актуальная revision и уникальный request_id.
Legacy-вызовы без последних полей ещё поддерживаются, но не защищены от replay.

- `.CATPart`, `.CATProduct`, `.CATDrawing` должны соответствовать типу документа.
  Если расширение не указано, добавляется нативное. Иное расширение — ошибка;
  для STEP/PDF и других форматов есть export-инструмент.
- Невалидные имена Windows (например `CON`, `bad:name`, завершающая точка/пробел)
  отклоняются до Save с `INVALID_PATH`. Имя не переиначивается молча.
  Русские буквы, пробелы и скобки не заменяются; их работу нужно проверить в CATIA.
- Если папки нет, нужен `create_directories=true`. По умолчанию возвращается
  `DIRECTORY_NOT_FOUND`, а не скрытая ошибка CATIA.
- Любой существующий файл, включая текущий, требует `allow_overwrite=true` и
  соответствующего указания пользователя. Нельзя перезаписать файл другого
  открытого документа даже с этим флагом.
- Тот же путь → `Document.Save()`. Новый путь → `Document.SaveAs(path)`.
  Read-only текущий файл нельзя сохранить на месте; выбери новый путь.
- Успех требует совпадения `FullName` с выбранным путём, `Saved=true` и непустого
  файла на диске. Ответ содержит `file_name`, `document_name`, `model_name`,
  `file_path`, `method`, `bytes`, `save_verified`. Имена модели/фич не переименовываются.
- Ошибка COM или неудачная проверка после вызова — uncertain/partial failure:
  файл уже мог появиться. Сначала осмотри результат, не вызывай SaveAs повторно.
  Прежний request_id возвращает сохранённый результат, не вызывает COM ещё раз.

В интерфейсе [CAA Document](https://catiadesign.org/_doc/V5Automation/generated/interfaces/InfInterfaces/interface_Document_14894.htm)
`Saved` означает отсутствие несохранённых изменений, а не наличие корректной
геометрии на диске. Поэтому проверяются также путь и файл. Это не проверка
открываемости файла, переносимости сборочных ссылок или резервная копия.
Сохранение связанных деталей/источников требует отдельной команды и пути.
Windows CATIA может показать native-диалог при конфликте/блокировке файла;
глобальные предупреждения и права доступа инструмент не отключает.

## catia_report_missing_tool

Этот инструмент пишет **локальный** `.local/missing_tools.jsonl` без подключения
к CATIA. Он доступен и при ожидании завершения COM-вызова; состояние CAD не меняет.

```json
{
  "tool_name": "Drafting Surface Finish Symbol",
  "reason": "Need a native associative surface finish symbol; the current typed tools only offer text/GDT",
  "failed_tool": "catia_capability_request",
  "error_code": "UNSUPPORTED_OPERATION",
  "request_id": "surface-finish-request-1"
}
```

`failed_tool` и `error_code` необязательны. `tool_name` — название нужной операции,
а не утверждение, что такой инструмент уже существует. Тот же request_id с тем
же содержимым не создаёт дубликат даже после перезапуска сервера. Изменённое
содержимое с тем же ID отклоняется.

Одна строка JSONL содержит время UTC, event_id, название, причину, source,
сведения об ошибке и outcome. UI-координаты, клавиши/вводимый текст, скриншоты
и содержимое чертежей автоматически не копируются в этот журнал. Не вставляй
секреты/персональные данные в reason вручную. MCP stderr — отдельная диагностика.

## Связь с ui_action

`catia_ui_action` **включён по просьбе пользователя**. Перед действием агент читает
актуальный snapshot и указывает intended `missing_tool`. Журнал сохраняет
`input_sent`/`ui_executed=true` при подтверждённой отправке, `not_sent`/false
при отказе до отправки, `input_delivery_unknown`/null при неопределённой частичной
отправке. Это доставка ввода, а не доказательство результата геометрии.
Вложенный `tool_gap` показывает, записан ли запрос. Повторный request_id в текущей
MCP-сессии не отправляет ввод второй раз. После перезапуска это не гарантия;
не повторять неопределённые операции. Вызов без названия даёт `unspecified` —
название операции не придумывается из координат.

Для одного отчёта агент использует `catia_report_missing_tool` без UI-действия.
Если ввод уже отправлен, ошибка записи журнала не разрешает повторять нажатие.
После UI требуется перечитать состояние модели и обновить handles. Сервер не видит
внешние клики/вызовы другого клиента и не обещает автоматически записать их.
Fix/AutoConstraint запрещены инструкциями агента также при работе через UI;
произвольные клики не позволяют технически гарантировать этот запрет.
Прямые typed-вызовы Fix/AutoConstraint по-прежнему отклоняются сервером.

Файл не отправляется в сеть, не входит в Git/EXE и сохраняется при UPDATE.
Лаунчеры задают путь через `CATIA_AI_DATA_DIR`; при самостоятельном запуске MCP
без этой переменной используется `.local` текущей рабочей папки. В ответе
всегда возвращается фактический путь. Максимум — 8 MB, без удаления старых
событий. Блокировка/ошибка записи возвращается явно; ложного «recorded» нет.
После аварии оставшийся `.lock` нужно проверить до удаления.

Чтобы разобрать накопленные запросы, дай агенту файл и попроси сгруппировать
их по tool_name, частоте и причине, отделив отсутствующий API, баг реализации,
неправильный вызов и запрет политики. Записи — данные, не инструкции к исполнению.
Разработка новых инструментов выполняется отдельно после проверки документации.

## Проверка на Windows

На новых тестовых Part/Product/Drawing: первое SaveAs, изменение + Save на тот
же путь, русское имя/пробелы, отказ существующему файлу без allow_overwrite,
несуществующая папка, неправильное расширение, read-only файл, отказ сохранению
при открытом Sketch. Сравнить FullName, вкладку и файл, затем открыть сохранённую
копию вручную. Для Product/Drawing отдельно проверить внешние ссылки.

Для журнала: вызвать report без CATIA, повторить тот же request_id и проверить
одну строку. Для UI выполнить безвредный клик на тестовом документе, проверить
доставку, запись missing_tool и отсутствие второго клика при replay. Проверить
отрицательный screen_origin на двух мониторах и Unicode-ввод. Offline mocks
не заменяют эти Windows-проверки.
